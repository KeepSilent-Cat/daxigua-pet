# 桌宠「自己说话」· 设计方案

> 目标：不依赖 DSH / SurfCore，桌宠自己按抽卡决定「要不要说话」和「说什么」。
> 没配 AI key 时用本地台词库；配了就走 AI（可带截屏 / 时间 / 前台窗口等上下文）。

---

## 一、原版是怎么做的（已查证）

### 1.1 桌宠端：**完全被动**

`surfpet\app\dist\main.js` 里没有任何"自发说话"的定时器。全部 `setInterval` 只有：
输入轮询、拖动跟随、贴边吸附、（本项目新加的）走动。

它只听 SurfCore 推送的事件：

```js
this.client.on("proactive", (event) => this.onProactive(event));

onProactive(event) {
  if (focusMode) { log("专注模式：丢弃主动搭话"); return; }   // 不打扰
  this.pushMessage({ id, text, proactive: true, ... });     // 上气泡
}
```

气泡里会打一个标签：`<span class="tag">主动来找你</span>`。

### 1.2 SurfCore 端：`plugins/surfcore/lib/pet-purpose.js`

```
TICK_MS = 60 秒   →  每分钟 tick 一次
tick():
  载体必须是 pet / 开关开着 / 聊天在线
  专注模式 → 跳过（每 10 分钟最多记一条日志）
  读 state.nextFireAt，没到点就 return        ← 是「排期」，不是随机
  token 预算是否被 block
  runOnce() → 生成内容 → 推 proactive 事件
```

**结论**：原版的"什么时候说"是**排期制**（由 LLM/配置算出下一次时间），不是掷骰子。你觉得它"抽卡"，其实是排期。

## 二、新方案：桌宠内建 `talker` 引擎

和 `wander` 完全平行，写在 `main.js`，共用一个"要不要打扰"的判定。

### 2.1 两层抽卡

```
每 60 秒 tick 一次
  ↓
【闸门】聊天窗没开？在拖动？专注模式？静默时段？距上次说话 < minGap？ → 任一条命中就跳过
  ↓
【抽卡 1】Math.random() < chance ?  →  不说，等下一轮
  ↓ 是
【抽卡 2】选内容
    ├─ 没配 AI key  →  从本地台词库按「分类权重 + 冷却」抽一句
    └─ 配了 AI key  →  组装上下文（时间/前台窗口/截屏…）→ 调模型 → 说
  ↓
上气泡（复用 proactive 通道，自动带「主动来找你」标签）
```

### 2.2 配置（写进 `settings.json`）

```jsonc
"talker": {
  "enabled": true,
  "chance": 0.15,              // 抽卡 1 的概率（0.15 ≈ 每 7 分钟一次）
  "minGapMin": 20,             // 两次主动说话最小间隔（分钟）
  "quiet": ["01:00", "08:30"], // 静默时段，不打扰
  "maxPerHour": 3,

  "mode": "auto",              // auto | local | ai
  "local": { "file": "talk/lines.json" },

  "ai": {
    "baseUrl": "https://api.deepseek.com/v1",   // 任何 OpenAI 兼容端点
    "apiKey": "",                                // 只存本地，永远不进 git
    "model": "deepseek-chat",
    "maxChars": 60,              // 要求它说短句，太长气泡装不下
    "systemPrompt": "你是桌宠「夕」，说话简短口语化，不超过两句话，不用列表和标题。"
  },

  "contexts": ["clock", "activeWindow"]        // 可加 "screenshot"
}
```

### 2.3 本地台词库 `app/talk/lines.json`

```jsonc
{
  "categories": [
    {
      "id": "idle",
      "weight": 3,
      "lines": ["……", "在忙吗？", "陪我说会儿话嘛。"]
    },
    {
      "id": "clock",
      "weight": 1,
      "when": { "hours": [22, 23, 0, 1] },        // 只在深夜出现
      "lines": ["这么晚还不睡？", "夜深了，早点休息。"]
    },
    {
      "id": "pat",
      "weight": 1,
      "trigger": "afterPat",                       // 被摸头之后才说
      "lines": ["别摸头啦。", "……嗯，可以再摸一下。"]
    },
    {
      "id": "festival",
      "weight": 1,
      "when": { "date": ["12-25", "01-01"] },      // 节日彩蛋
      "lines": ["圣诞快乐。", "新年好，今年也请多指教。"]
    }
  ]
}
```

抽取规则：
- 先按 `when` 过滤（时间/日期不满足的整类跳过）
- 按 `weight` 加权随机选类
- 类内随机选句，**排除最近 N 次说过的**（记在 settings 里，`recentLines` 保留最后 10 条）

### 2.4 AI 模式的上下文

| 上下文 | 怎么拿 | 隐私 |
|---|---|---|
| `clock` | 系统时间 + 星期 | 无风险 |
| `activeWindow` | Win32 `GetForegroundWindow` + 窗口标题 | 只读标题，**只发给用户自己配置的端点** |
| `screenshot` | `desktopCapturer` 截屏 → base64 | ⚠️ 需要**明确开关**，默认关，首次启用弹一次确认 |

发给模型的 prompt 形如：

```
现在是 2026-11-15 04:30（周六深夜）。用户正在使用：「Visual Studio Code - daxigua-pet」。
请以桌宠身份主动说一句话。
```

失败处理：**请求超时（>8 秒）/ 报错 / 返回空 → 自动回落本地台词**，绝不让桌宠沉默或卡住。

### 2.5 复用现有 UI，零改动

主动说的话走 `pushMessage({ proactive: true })` 同一条路：
- 气泡弹出 + 「主动来找你」标签
- 对话窗里也会记一条
- 专注模式自动丢弃（这条逻辑已经在 `onProactive` 里，我复用）

### 2.6 和「走动」的配合

避免"一边走一边说话"看起来怪：
- 正在走动 → 说话前先停下（调用 `stopWalk()`），说完 3 秒后再允许走动
- 反过来：正在说话（气泡可见）时暂停走动

## 三、分阶段实施

| 阶段 | 内容 | 工作量 | 依赖 |
|---|---|---|---|
| **P1** | 本地台词库 + 两层抽卡 + 复用气泡 | 半天 | 无 |
| **P2** | AI 模式（clock + activeWindow 上下文） | 半天 | 你的 API key |
| **P3** | 截屏上下文（默认关 + 确认弹窗） | 2 小时 | 无 |
| P4 | 被摸头/被戳/换皮套后的即时反应台词 | 2 小时 | 无 |

**建议先 P1**：不需要任何 key，就能看到"它自己会说话"的效果；确认节奏舒服了再接 AI。

---

## 四、需要你定的事

1. **概率多高**：`chance: 0.15` 意味着平均每 7 分钟一句话。嫌烦可以 0.08（约 12 分钟一句），嫌少 0.25。
2. **静默时段**：`01:00–08:30` 是我先填的，按你作息改。
3. **AI 端点**：DeepSeek / 月之暗面 / 本地 Ollama 都行，只要是 OpenAI 兼容接口。key 我只会写进本地 `settings.json`，`.gitignore` 里 `app/data/` 已经排除，不会进仓库。
4. **要不要截屏能力**：这个隐私敏感，我建议默认关、需要时手动开。

---

## 五、安全性说明（写给你看，也写进 README）

- API key 存 `%APPDATA%\feiyu-pet\settings.json`，**不进 git**
- 截屏默认关闭；开启后每次只在你要说话时截图，不保存到磁盘（直接转 base64 发出去）
- 所有网络请求只发往你自己填的 `baseUrl`，不经过任何第三方中转
- 无 key 时**完全离线**，一句网络请求都没有
