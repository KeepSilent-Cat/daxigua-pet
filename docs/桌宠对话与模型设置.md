# 桌宠对话与模型设置（怎么把你现在用的 API 接进去）

> 结论先给：**桌宠自己不调 API，也没有填 key 的地方。**
> 它只认本机 SurfCore 插件写的一个发现文件；模型是在 SurfCore / DSH 那一侧配的。

---

## 一、链路是这样的

```
  桌宠进程 (surfpet, Electron)
        │  读 ~/.dsh/surfcore/pet/host.json 拿到 { baseUrl, token }
        ▼
  POST http://127.0.0.1:<DSH端口>/dsh-surfcore/pet-api/chat
       header: x-pet-token: <token>
        │
        ▼
  SurfCore 插件（跑在 DSH 里）
        │  用 config.json 的 dsh.provider / dsh.model 调用
        ▼
  DSH 的 llm 服务  →  provider（api.deepseek.com 或你的中转）  →  模型
```

所以：

- **surfpet 里没有 API key 相关代码**，它只往本机回环地址发请求
- 你「现在用的这个 API / 模型」，实际配置位置在 **DSH 的模型设置**，SurfCore 默认跟随
- 没装 SurfCore 时，桌宠会一直打印：`[chat] surfcore offline: 还没找到 SurfCore（~/.dsh/surfcore/pet/host.json）`

## 二、模型在哪配（关键）

SurfCore 的 `config.json` 里有这么一段（**下面是已经按你这台机器填好的实际值**）：

```jsonc
"dsh": {
  "baseUrl": "http://127.0.0.1:3999",     // 你这台 DSH web 就走 3999
  "provider": "wmianbao",                 // ← 你现在用的那个中转
  "model": "deepseek-v4.1-flash",
  "reasoningEffort": "low",               // 闲聊场景压速度/省 token
  "followDefaultModel": false,            // 已写死成上面那个，不跟 DSH 默认走
  "authToken": "",                        // DSH 网关的鉴权，不是模型 key
  "authHeader": "authorization",
  "authPrefix": "Bearer",
  "allowRemote": false                    // 只允许回环，安全边界
}
```

> 你的模型不是官方端点，是**中转**：`https://wmianbao.top/v1`，
> key 走环境变量 `DEEPSEEK_API_KEY`。这些原本写在
> `D:\work_project\dsh-local-data\profiles\web\cordis.patch.yml` 的 `llm-pi-ai` 段里，
> 也就是「我现在用的这个 API」。

三种情况，对号入座：

| 你想怎样 | 怎么配 |
| --- | --- |
| **就用 DSH 现在默认的模型**（也就是我现在这个会话在用的） | `followDefaultModel` 保持 `true`，什么都不用改。模型跟着 DSH 设置 → 模型走 |
| **固定用某个特定模型** | `followDefaultModel: false`，然后填 `provider` + `model`（值必须是 DSH 里已注册的 provider / model id） |
| **用你自己的 key 或中转站** | 在 **DSH 的模型/provider 设置**里加一个 provider（填 baseURL + apiKey），再把上面的 `provider`/`model` 指过去。**不要把 key 写进 SurfCore 的 config.json** |

> `allowRemote: false` 意味着 `dsh.baseUrl` 只能是本机回环地址。
> 想连远端中转，请把它注册成 DSH 里的一个 provider，而不是直接改这个 baseUrl。

`reasoningEffort`（思考强度）会影响回复速度和 token 消耗，桌面闲聊建议 `low` / `medium`。

## 三、安装 SurfCore（要对话必须先做这步）

前置：Windows + **Node ≥ 22.13** + **DSH ≥ 0.2.1-rc.2**（先确认版本，低了装不上）

> ⚠️ **这一节是「标准安装包版 DSH」的做法。你这台是源码构建，不能照抄**，
> 实际采用的替代方案见第八节（只装 bundle、跳过 QQ preset），已经做完了。

标准流程（备查）：

```powershell
git clone https://github.com/Mieksido/surfcore
cd surfcore
npm install                                   # 必须在仓库根跑，不能只装 plugins/surfcore
copy config.example.json config.json          # 然后编辑，只需填 4 处左右
node scripts/setup-dsh.mjs <profile名>        # 默认 web
```

然后：

1. **重启 DSH**（客户端模块图是页面加载时的快照，不重启设置里看不到）
2. 打开 **设置 → SurfCore → 诊断 → 一键安装（全部）**
3. **设置 → SurfCore → 桌宠**：
   - 「Electron 路径」填 `D:\mvp_project\deepseekagi\surfpet\runtime\electron.exe`
   - 「安装包地址」填 `pet-pack.zip`（官方 Release 那个，或把这个 `app` 目录重新压成 zip）
   - 点 **安装** → 点 **启动**

装完之后，桌宠由 SurfCore 管理，`host.json` 才会存在，对话才通。

> ⚠️ 这套安装会改 DSH 的 profile（加 preset、3 个 MCP server、1 个 bundle）。
> 属于比较重的改动，装之前建议先把 `~/.dsh` 里的 profile 备份一份。

## 四、装完怎么调对话

| 位置 | 能调什么 |
| --- | --- |
| 设置 → SurfCore → **桌宠** | 启用对话开关、**回复字数上限**、**上下文轮数**、**思考强度**、把桌宠对话写进记忆卡（默认开） |
| 设置 → SurfCore → **目的** | 主动搭话的载体（桌宠 / QQ）、文本还是语音、节奏与安静时段 |
| 设置 → SurfCore → **语音** | TTS 路由：本地（8765）/ 云端（8767）、音色、字数上限 |

桌宠侧的操作：

- **右键 → 文本对话 / 语音对话**
- 她说的话显示在头顶**气泡**里，气泡带「回复」按钮
- **右键 → 专注模式**：暂停自动主动搭话（你主动找她聊仍然正常）

## 五、人设从哪来

桌宠的人设不完全在皮肤里，是两层叠起来的：

1. `skins/<id>/persona.md` —— 这个**皮套自带**的人设片段
2. SurfCore 的**角色人格卡** + 记忆卡（`~/.dsh/surfcore/characters/<id>/persona.md`，会随时间衰减）+
   「目的」状态里的动机

所以换皮肤会换掉一部分人设，但长期记忆是跟着 **SurfCore 的角色**走的，不跟皮肤走。

## 六、数据落在哪

```
~/.dsh/surfcore/pet/
  host.json                 { baseUrl, token, api, pluginVersion }   ← 桌宠靠它找接口
  host-token                本地令牌（0600）
  focus.json                专注模式
  config.json               { source, electronPath, appDir, installedAt }
  app/                      解压后的桌宠（skins/ 就在这里）
  chat/history-<角色id>.json 对话历史（按角色隔离，换皮套不串台）
  voice/                    TTS 缓存（wav）
```

桌宠专用接口（**只能用** `x-pet-token`，不能用 DSH 会话 Cookie）：

| 方法 | 路径 |
| --- | --- |
| GET | `/dsh-surfcore/pet-api/health` |
| GET | `/dsh-surfcore/pet-api/status` |
| POST | `/dsh-surfcore/pet-api/chat`　`{ text, modality }` |
| GET | `/dsh-surfcore/pet-api/events?since=&wait=`　长轮询，收主动搭话 |
| POST | `/dsh-surfcore/pet-api/focus` |

## 七、成本与安全

- 对话**走模型、算 token**，会记到 SurfCore 的 token 额度里。闲聊场景把回复字数和思考强度压低
- `host.json` 里的 token 只在本机回环使用，别外发
- **key 不要写进仓库**：`config.json`、`state/`、`~/.dsh` 里的凭据都属于本地机密
- 桌宠是独立 Electron 进程，SurfCore 退出不会带走它；要停得手动停

## 八、当前这台机器的实际情况（实测，跟官方文档不一样，务必看）

你这台 DSH **不是**官方安装包跑的那套，而是**源码构建 + 独立数据目录**：

```
进程    : node --import tsx/esm apps/cli/src/bin.ts web --host 127.0.0.1 --port 3999
源码    : D:\work_project\dsh-source-archive\deepseek-harness-master
DSH_HOME: D:\work_project\dsh-local-data      ← 注意不是 ~/.dsh
profile : web                                  ← 不是 desktop
版本    : 0.2.2-rc.1（源码树）
```

这带来一个官方文档没覆盖的坑：

| 现象 | 原因 |
| --- | --- |
| `verify-dsh-020-adaptation.mjs` 报 `Cannot find module @deepseek-ai/dsh-persona` | 这版源码树里**没有 persona 包**（只有 `dsh-agent`） |
| 直接跑 `setup-dsh.mjs` 有风险 | 它会把两条 **QQ agent preset** 插进 profile，而那些 preset 的 `plugins` 里引用了 `dsh-persona`，可能导致 DSH 起不来 |

**所以实际采用的是「只装 bundle、跳过 QQ preset」的方式：**

1. `npm install`（已完成，128 个包）
2. `config.json` 指向 `http://127.0.0.1:3999` + 你的 `wmianbao / deepseek-v4.1-flash`（已完成）
3. `profiles\web\node_modules\surfcore` → junction 指向 `.upstream\surfcore\plugins\surfcore`（已完成）
4. `profiles\web\package.json` 的 `dsh.profile.bundles` 加一项 `surfcore`（已完成）
5. 把 bundle 的 `dsh.bundle.patch` 从三行改成只留 `./cordis.patch.yml`
   —— 去掉 `qq-chat.patch.yml` / `qq-chat-v2.patch.yml`（已完成）

**代价**：QQ 桥接、B站、两条 agent preset 不可用；**桌宠 + 对话 + 记忆卡**这条链路不受影响。
哪天你这版 DSH 补回了 `dsh-persona`，把 `plugins\surfcore\package.json.orig` 覆盖回去即可恢复完整功能。

**回滚**：运行 `回滚SurfCore安装.ps1`，或用 `state\dsh-local-backup-*.zip` 覆盖 `profiles`。

| 检查项 | 结果 |
| --- | --- |
| `~/.dsh`（另一套，desktop profile） | 存在，但**跟当前运行的 DSH 无关**，不要动 |
| `~/.dsh/surfcore` | 不存在（正常，用不到） |
| `D:\work_project\dsh-local-data\profiles\web` | 已注册 surfcore bundle |
| `state\pet-pack.zip` | 已打好（15.5 MB，给 SurfCore 设置页装桌宠用） |

现状：桌宠是我用 `小肥鱼桌宠.exe` 独立起的，**还没走 SurfCore**，所以仍然 `surfcore offline`。
重启 DSH 之后，在 **设置 → SurfCore → 桌宠** 里装 `state\pet-pack.zip` 并启动，对话才会通。
